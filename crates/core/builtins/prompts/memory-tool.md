Your memory across chats, kept by Themis outside the project. Save what will be worth knowing in a later chat: the person's preferences, corrections they gave and why, decisions and their reasons, facts about the project that its files do not record, and pointers to outside resources. Do not save code, file contents, chat history, anything the repository already records, or secrets (secrets are removed anyway).
Types: "user" (about the person) and "feedback" (how they want work done; add why and how_to_apply) may have scope "global" when they hold for every project, and then name nothing specific to one project (no paths, repository or client names, code). "project" (facts about this project; add why and how_to_apply) and "reference" (where to find things outside it) always have scope "project", the default.
Actions: "save" a new memory with a kebab-case name, a one-line description, its type and body; "update" an existing memory by name instead of saving a duplicate (give every field again); "delete" one that turned out wrong or no longer holds; "read" one in full. When a memory is built from a web page or a file rather than from the person, set source to say which.
