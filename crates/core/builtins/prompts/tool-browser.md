Use the built-in browser, which the person can watch in Workspace and may use at the same time. Runs JavaScript, unlike fetch_url. Pick what to do with action; each action reads only the fields that name it. Elements are named by a ref from the latest snapshot like e14, a CSS selector like .card, or text=Some text. Every action that touches the page returns a fresh snapshot: an outline with refs like [e12] for elements you can act on, plus new_since_last_action (console errors, failed requests, dialogs).
- open: open url. Example: {"action":"open","url":"http://localhost:5173/signup"}
- navigate: direction back, forward or reload.
- snapshot: read the page again, only when it changed on its own or to read one part (reference).
- click: an element by reference (buttons, links, checkboxes, tabs), or a point of the visible page by x and y in CSS pixels when there is no ref (a canvas, map or game). Examples: {"action":"click","reference":"e14"}, {"action":"click","x":412,"y":230}
- type: text into a field, optionally clearing it first and pressing Enter after (submit). Example: {"action":"type","reference":"e12","text":"test@example.com","clear":true}
- select: choose options of a <select> by value or label. For custom dropdowns, click them and then the option. Example: {"action":"select","reference":"e9","values":["Germany"]}
- press: a key in the focused element, or hold it with hold_ms. Also mouseDown and mouseUp, to hold the mouse button: move there, mouseDown, move across, mouseUp.
- scroll: the page (or one scrollable element) by most of a screen, for infinite feeds and content that loads as you scroll. Snapshots already include off-screen content.
- move: the mouse, without clicking; under_mouse in the result says what it is over. x and y go to a point, as for a hover menu; dx and dy move by a distance from where the mouse is, to aim in a game, where the view turns with the distance moved and a page holding the pointer lock has no edge. A snapshot cannot show what a canvas draws: read where things are with devtools, then act with move and click, since only real input tests the page.
- drag: press the mouse at one place, move to another and let go, as a person drags: a card between columns, a slider, a shape on a canvas. Each end is an element or a point. It is real input, for pages using native drag and drop and for pages listening to the mouse. drag in the result says what was pressed on, whether anything was dragged, and where it let go.
- check_looks: measure how the page looks, in both light and dark colour schemes (the page switches briefly and is put back): text or controls too faint to see against what is behind them, buttons and fields with no visible text or edge, content cut off or off the side of the page, source code showing as page text, CSS rules the browser dropped as invalid, quirks mode, stylesheets, scripts, images or fonts that failed to load, and console errors. Elements carry refs like the snapshot. It finds what can be computed, not every visual problem: colours over images and gradients are not checked.
