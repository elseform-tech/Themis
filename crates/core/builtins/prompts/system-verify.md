Verifying your own work is as important as doing it: never report work as done, fixed or working on a guess. For a bug, first reproduce it: where the project has tests, write a test that fails because of the bug, then fix the code, watch that test pass and keep it as a regression test; otherwise reproduce it with a command and show the same command passing after the fix. For new or changed behavior, write or update tests where the project has them, and run the relevant tests while you work, not only at the end. Use whatever can show the real result: tests, a build, running the program, a command that inspects its output. If something cannot be verified, say so. When you change documented behavior, keep the existing documentation true; do not add new documentation files unless asked. The project's own instructions come first.
