# Themis UI rules

Follow the [product design rules and color system](../DESIGN.md). Polish the existing workspace; preserve its conversation and review workflows.

- Keep a permanent icon-only utility rail. Each icon has one clear tooltip and accessible name. The expandable dock contains Themis, New chat, a project switcher and one Chats list for the chosen project (most recent first, 12 shown, then Show more) under a small, dimmed, divided CHATS label with a count, so the label never reads as a chat row. Each chat row has a speech-bubble icon in the folder-icon column so titles align with the project name, and the active chat sits in a soft pill. Project names and chat titles that do not fit scroll slowly to their end and back; reduced motion wraps them instead. The switcher lists projects with chat counts, marks projects with live work, and holds New project, Rename project and Delete project (not for the built-in Themis project; it asks for confirmation and says the folder moves to the Trash); projects live in the fixed projects folder, so there is no Open folder action. Long project names in the menu stay inside it and reveal on hover. Thread rows show an indicator only for live work (spinning arc), waiting for approval (pulsing pause), failure (red alert) and a run that finished in the background and has not been opened yet (green check, cleared on open). Dragging the sidebar or Workspace edge moves only the width and commits it on release; a thin accent line marks the edge on hover, and double-click resets it. Opening Workspace on a window narrower than 1500 px folds the sidebar to its rail and closing Workspace restores it. Animate its width with the canvas so collapse/expand moves smoothly; reduced motion uses an immediate toggle.
- Keep Themis in the sidebar at `~/ThemisOS/Projects/Themis`, without a lock or name protection. All new projects live under `~/ThemisOS/Projects`. No setting or creation action changes this root. Settings shows only the shared projects root. Renaming any project, including Themis, changes its display name only; folders and history stay in place. Existing folders are never moved automatically.
- Edit thread changes only its name. The thread header's model pill selects the model and reasoning effort between runs. Each completed response displays its captured model, including after restart or a later switch. Never infer old response models from the current selection; use “Model not recorded” for missing historical metadata.
- Use dark mode only. Offer 17 coordinated templates, including GitHub Dark and Dimmed, plus 12 local font choices and 12–22px text sizes. Preview changes throughout the app; Apply saves, Revert or leaving Settings restores saved choices. Code remains monospace.
- Buttons are unboxed: text or icon only, no filled or outlined containers. Primary actions use the accent color; selection uses brighter, bolder text. The composer is one rounded pill with a **+** menu (attach, skill, plugin), the YOLO/Custom shield, the context meter and send, and a quiet row showing the project directory and current Git branch. Cards group a meaningful unit (an automation, a review item, a settings section, an integration tile). Keep settings labels short while retaining necessary permission explanations.
- Show the selected thread with bright, bold text, without a background or colored side stripe. Thread options (rename, remove) live in a ⋮ menu revealed on hover or focus. Use continuous surface layers in every palette: lighter icon/header frame, dark collapsible sidebar, darker canvas. Separate them through their backgrounds, without bright outlines or frame gutters. Appearance swatches and the live surface preview show this same order.
- Overflowing project and thread names start at the beginning, then move right to left on hover or keyboard focus. Preserve their full accessible names. Reduced motion wraps titles and disables motion and shimmer.
- Use the Honey, Pearl and Ink **Bubbles** artwork (bubble blobs drawn from the original blob knight body) for startup and the optional floating companion. Keep other UI surfaces free of companion decoration; retain native app icons and favicon and the glinting Themis wordmark in the expandable dock.
- Put a Bubbles icon in the permanent left rail. One click opens a small popover with the three variants, a Companion checkbox and a 56–192px size slider; the icon reflects the selected variant and stays available when hidden or the dock is collapsed. Remember variant, visibility, size and position locally. On desktop, use a separate transparent always-on-top window that moves outside Themis and over other apps. Provide a visible drag grip, free positioning and keyboard arrow movement; follow the global mouse position with its gaze. Browser previews stay within the canvas above the composer. Use no edge snapping or surrounding container. Speech is limited to two short state notes: “All done!” for about six seconds after completion and “Needs you” while approval or an error needs attention. Closing the main window also closes the companion. Respect reduced motion for blinking, breathing, gaze and reactions.
- Startup shows the selected bubble while preferences, workspace and conversation restoration actually run; no artificial loading delay or progress percentage. Failures dismiss the loader and retain the existing error notice. The companion reacts to the selected conversation's running, completed and approval/error states. Pointer and keyboard interactions remain available without motion.

Verification belongs in [UI polish checks](ui-polish-verification.md); appearance details are in [Desktop appearance](appearance.md).
- New chats show a greeting (“Hi there.” in the warm gradient, then the project question), the composer centred, and up to four starter chips (project skills first). The first message moves the composer to the bottom.
- Run activity collapses into “Show thinking · N tool calls” chips; completed replies offer Copy beside their model label. A context checkpoint renders as a centred “Context compacted · before% → after%” divider.
- The composer's context meter shows byte-estimated usage of usable message space from the runtime's `context_budget` events. Its popover breaks usage into tool activity, messages, attachments, checkpoint and task ledger, and system instructions, lists tool-definition, reply and safety reserves held outside the bar, and states the tidy-up and auto-compact thresholds. While a run is active and growth projects compaction, the chip turns warm and a dismissible heads-up appears once above the composer. There is no manual compaction or retry control.
- **Workspace** in the thread header opens a read-only monitor of what agents write, never a review or Git-action surface: Changes (folder-grouped changed files, with a filter only for long lists, beside a unified diff that refreshes after each completed tool call, every few seconds during a run and when the run ends), Files (project tree and read-only file view), Branches (local branches, upstream and tracking) and Pull requests (open PRs from the GitHub CLI when installed and signed in, otherwise the reason). It shows the project name and branch, and its width is adjustable by drag or arrow keys and remembered. It offers no accept, discard, merge, comment, commit or push action. The only state-changing controls are Stop and Pause on Tasks rows.
- **Tasks** is the fifth Workspace tab, with a small count of items that need attention, run or are scheduled. It covers the current chat only and groups rows as Needs attention (a run waiting for approval, an unseen failed automation run), Running, Scheduled (this chat's automations; paused ones are listed without buttons and are resumed in Automations) and Earlier (recent finished or failed automation runs, plus automations that ended, newest first, with the reason: completed by agent, expired, run limit, failed 3 times, chat deleted or deleted; a past run keeps its automation's name and "by agent" tag after deletion). A Scheduled watch row reads like "Every 2 min · until status.txt says DONE · expires 21:30 · next ..."; a user's automation paused by the failure backstop reads "Paused · failed 3 times". A row has a status icon, name, kind tag (Run, Automation · continues this chat, Automation · by agent), a meta line (schedule, next run, last result) and Stop (stops the chat's current run) and/or Pause (turns the automation off). The footer reads "Shows this chat only. Stopping never undoes work already done." Background shell tasks started by the agent appear as rows too (see below); conversation notice cards are not shown.
- A **background task row** (`BackgroundTaskRow`) shows the command in monospace, the tag "Background task", a meta line ("Started 14:05 by agent · ends when this chat closes · port 1420"; the port is read from recent output when present), the last three output lines in an inset block, **Stop** (running only) and **Full log**, which loads the whole bounded 64 KiB log read-only and toggles to "Hide log". Running tasks are listed under Running, timed-out or non-zero-exit tasks under Needs attention, stopped or clean exits under Earlier. A task lost to a server restart is listed under Earlier with "lost after restart; the program may still be running" and does not light the indicator (it cannot be dismissed). **Full log** is hidden when the preview already shows the entire output. The port in the meta line is parsed from recent output (`localhost:N`, `127.0.0.1:N`, `0.0.0.0:N` or "port N") and is omitted when the program prints none. Stop stops only that task. No other task control exists.
- The **task indicator** sits left of the Workspace button in the thread header: up to three overlapping 24 px circular icons in the order needs attention (red alert), running (blue spinning arc; no spin under reduced motion), scheduled (amber clock), finished and unseen (green check), then "+N" for the items of any further kind. It is hidden when the chat has nothing active, is named like "Tasks in this chat: 1 needs attention, 2 running, 1 scheduled. Opens Workspace tasks", and opens Workspace on the Tasks tab. It refreshes from run, approval, tool, automation, review and background-task events (`background_tasks_changed`), never by polling. Running background tasks count as running; timed-out or failed ones as needs attention.

- Utility pages (Integrations, Automations, Review queue, Settings) share one centred column with an unboxed title and divided rows instead of cards. Filters stay on one toolbar line; result counts and Reset filters appear only while a filter is active. Automation and Settings on/off choices use switches; secondary row actions appear on hover or focus. Search lists only automations once there are more than four.
- Search (⌘K) is a single borderless field with Chats, Projects and Actions groups, short project names instead of paths, and a short list when the query is empty. Help lists shortcuts with key caps.
- Sent attachments sit above the user's message: images, videos and PDFs as rounded thumbnails, other files as compact chips with their extension. An unavailable preview falls back to the chip.
- The Workspace change list shows only readable text: binary files, compiled artifacts (`.pyc`, `.o`, …), `.DS_Store` and cache folders (`__pycache__`, `node_modules`, `.venv`, …) are left out, and a short note counts what was hidden. Deleted files stay listed. Diffs and the file view wrap long lines under their text column with syntax colours instead of scrolling sideways.
- After a turn ends, its reply lists the files that turn edited (“Edited N files”, with A/M/D status and the folder dimmed). The list compares the project's changed files before and after the run, so edits made with shell commands count, earlier edits do not, and binary or generated files are left out. Selecting a file opens Workspace on that file's diff. The list is saved with the conversation.
- **Approval dialog.** Buttons are **Allow once (1)**, **Allow in this chat (2)** and **Deny (3)**; destructive requests (`grantable: false`) show only **Allow once (1)** and **Deny (2)** plus a fixed sentence that the action always asks. "Allow in this chat" is worded from the approval event's structured `grant_scope` (raw argv tokens plus whether later arguments are covered), derived from the same prefix as the grant key. For `shell` the dialog shows each covered token as its own monospace chip (tokens with whitespace are quoted, control, bidi and zero-width characters appear as `⟨U+XXXX⟩`, at most 12 tokens of 80 characters, with explicit "…(+N more)" markers) followed by "and any further arguments" when a program + subcommand prefix is covered; the sentence is fixed text, never built from argv. Other tools say the grant covers "this tool", and MCP tools say it covers every tool of that server. A request that times out is removed by the `approval-expired` event with the note "Approval expired — the action was skipped". There is no UI for revoking chat grants (edit the chat's grant file or start a new chat); the 500 ms digit delay applies. Digits 1/2/3 decide only outside the composer and form fields.
- **Interrupted runs.** Stop or a failure keeps the text already streamed as an assistant message marked "Stopped by you" or "Interrupted by an error" (saved in the transcript as streamed text before the terminal event, so it reloads the same), followed by the usual Stopped/Request failed note.
- **Composer.** Single-key shortcuts never fire from the composer, the shield or form fields. A mouse press on the shield does not move focus to it; the Approval mode select ignores typed letters (arrows, Space and click still work); clicking the box outside its controls focuses the text area.
- **Live sync.** Chats created, renamed or changed (approval mode, effort, skills) or discarded through the shared server (`themis call …`, another client) arrive as `thread-changed` events (`created|updated|removed`, metadata only) and update the open window's sidebar and shield without a reload; replays are harmless and the current selection is kept.
- Tasks "Earlier" summaries and the review toast show plain text: markdown is flattened (display-only, capped, not a sanitizer) and the toast uses the stored automation name, "(by agent)" tag and a friendly time instead of the raw timestamped title. Inline code in "Show thinking" notes keeps its normal text colour.
- Shell and git approvals carry the whole command as structured `command` (`argv`, `cwd`, `background`); the dialog renders it as chips and never shows the joined summary for them. Only letters, numbers, punctuation and symbols are shown literally in a chip; anything else (controls, bidi, zero-width, combining marks, variation selectors, blank-looking letters such as U+3164 or U+2800, and the escape brackets themselves) becomes a highlighted `⟨U+XXXX⟩` escape, and a token with an escape is quoted. Digit shortcuts in the dialog start 500 ms after it opens and ignore key repeat.
