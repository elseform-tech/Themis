# Maintenance evidence retention (2026-10-11)

The same-chat 200k narrative trial `1f27d0aa-e9b4-46de-9db8-7a818949186f` was stopped after review confirmed a harness defect. Cheap maintenance replaced old plain-file and shell observations with 256-byte previews before semantic summarization consumed them. Specific relevant passages lay beyond those previews and outside the recent-message tail. Immutable originals remained intact; at least two passages were reacquired later. This establishes evidence loss and recovery risk, not that every subsequent query was caused by the defect or that the run entered an infinite compaction loop. It installed no checkpoint and produced no accepted answer.

The patch preserves delivered ordinary tool results, including plain reads, shell output, MCP output and results with missing invocation provenance. Validated original-derived JSONL read pairs retain the selectors needed by summary projection. Completed invocation arguments remain offloadable. Strict non-executable receipts retain their pre-offload original/recovery classification, so an archive pointer cannot silently exclude surviving ordinary evidence from a subsequent checkpoint. Saved classification applies only to the four native recovery-sensitive names; operational, malformed and legacy envelopes use the existing conservative classifier. No permission or truth label is introduced.

Maintenance now plans net savings before publishing an immutable snapshot. Mixed protected results with a tiny redundant sibling do not create repeated full-context archives when receipts would expand context. Public-intent notes use a basename and a fixed conservative excerpt allowance; long escaped directories and shorter actual snapshot names cannot invalidate the planning bound.

## Live evidence and limits

All six matching document capsules were reused. All-attempt 200k accounting through this stop includes 23 runs and 300 known request attempts; 21,817,896 known input tokens and 181,864 output tokens are lower bounds with missing usage. This is not an efficiency gain or successful task acceptance.

Occupancy reduction does not establish factual retention or billing savings. The new patch requires a rebuilt packaged rerun in the same chat with the same source/prompt/model constraints.
