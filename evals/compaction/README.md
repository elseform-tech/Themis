# Compaction checkpoint evals

A repeatable measurement of how much a conversation keeps after Themis compacts it.
This is a **live-model benchmark audit**, separate from the automated runtime checks.
It is never run in CI against a real model; CI only proves the plumbing offline
(`python -m unittest evals.compaction.test_harness` and
`cargo test -p themis-core --features eval --test compaction_eval`).

## How it works

1. `crates/core/src/runtime/eval.rs` (cargo feature `eval`, never in releases) replays a
   fixture transcript and **forces** one compaction after each chunk boundary through
   the same internals a run uses (`compact_context_with_evidence`, with saved originals),
   so repeated compactions exercise prior-checkpoint carry-over.
2. After the last compaction every probe question is asked using only the post-compaction
   working messages: no tools, no archive access. Answers must be short or exactly `UNKNOWN`.
3. `python3 -m evals.compaction run` grades answers deterministically and writes
   `evals/compaction/results/<date>-<model>-<budget>.json`.

The runnable is `crates/core/examples/compaction_eval.rs`
(`required-features = ["eval"]`); the harness builds it for you.

## Run

```sh
export OPENCODE_KEY=...   # never commit or print it
python3 -m evals.compaction run --suite core --trials 3 \
  --model longcat-2.5-preview-free --budget 24000
```

Options: `--case NAME` (repeatable), `--jobs N` (parallel runs, default 3),
`--recent N` (verbatim tail messages, default 20 like the app), `--timeout S`,
`--base-url URL` (mock provider; no key needed), `--runner CMD` (skip the build), `--out FILE`.
Run a single case directly with
`cargo run --release -p themis-core --features eval --example compaction_eval -- --case evals/compaction/cases/<name> --model M --budget 24000`.

## Grading

Per probe: `correct` (an `any_of` substring or the `regex` matches, case-insensitive),
`unknown` (answered `UNKNOWN` for a fact that was in the conversation: forgotten),
`stale` (matches a `stale` pattern of a superseded value and not the current one),
`wrong` (neither), `error` (provider failure). Decoy probes ask for facts that were never
stated; any answer other than `UNKNOWN` counts as `invented`.

Reported, as mean and sample SD (plus min/max) across trials: retention overall, per
category and per position (early/middle/late third of the transcript by where the fact was
planted), stale-fact rate (over probes that define stale patterns), forgot rate, wrong
answers, invented decoy answers, compaction latency, estimated tokens before/after, and
provider requests per compaction. Decoys never count towards retention. `failed_runs` lists
runner crashes/timeouts, which are excluded from the statistics rather than counted.

Grading is lexical: a correct paraphrase that avoids every expected pattern is scored wrong,
and a hedged answer that names the new value passes even if it also mentions the old one.
Treat small differences between runs with a single trial as noise.

## Cases

`cases/<name>/` holds `transcript.jsonl`, `probes.json`, `case.json`.

- `transcript.jsonl`: one record per line: `{"role":"user"|"assistant","content":...}`,
  assistant tool calls `{"role":"assistant","content":"","tool_calls":[{"id","name","arguments"}]}`,
  and tool results `{"role":"tool","results":[{"id","name","output"}]}`.
- `case.json`: `name`, `kind` (coding, parked_topic, superseded, narrative), `suites`,
  `records`, `chunks` (ascending record counts after which a compaction is forced; the last
  covers the whole transcript) and `next_action`.
- `probes.json`: `id`, `category`, `question`, `planted_at` (1-based record number holding the
  fact; sets the position bucket), `expected` (`any_of` and/or `regex`), optional `stale`
  regexes, or `expect_unknown: true` for a decoy.

Fixtures are synthetic and generated by `python3 -m evals.compaction.gen_cases`
(facts hand-written, filler generated from a fixed seed). To add a case, write a builder in
`gen_cases.py`, register it in `main()`, regenerate, and commit the output. Keep each chunk
below the budget (about 12-15k estimated tokens for the 24k budget) and plant facts early,
middle and late. Run `python3 -m unittest evals.compaction.test_harness`; it checks fixture
shape and the Rust test replays every case.
